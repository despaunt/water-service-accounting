# Учёт отпуска услуг водоканала

Лабораторная работа 4 по командному проектированию и разработке. Учебная конфигурация для платформы 1С:Предприятие 8.3.27, со встроенным языком BSL и отдельной файловой информационной базой. В рабочем проекте ВКР аналогичные объекты планируется использовать в 1С:Комплексной автоматизации. Здесь один документ соответствует одной услуге по одному объекту за период.

- `app/models/Catalogs` — справочники договоров, объектов расчётов и услуг.
- `app/models/Documents/РасчетОтпускаУслуг.xml` — модель расчёта, ссылки на объект и услугу, период, объём, тариф и сумма.
- `app/models/CommonModules/РепозиторийРасчетов/Ext/Module.bsl` — создание, чтение, выборка по периоду, изменение объёма и тарифа, пометка на удаление. Использую объектную модель и запросы 1С, поэтому устанавливать отдельную ORM и обращаться к таблицам СУБД напрямую не требуется.

## Миграция 1.0.0 → 1.1.0

На версии `v1.0.0` в отдельной чистой файловой базе создаю договор, объект расчётов, услугу и документ за октябрь. Объём 30 м³ и тариф 42,50 ₽/м³ дают 1 275,00 ₽.

Затем загружаю исходники 1.1.0 из ветки `feature/water-service-migration` в ту же базу и выполняю в Конфигураторе «Обновить конфигурацию базы данных» (F7). У документа появляется строковый реквизит `Примечание` длиной 250 символов. Реквизит необязательный, у прежних расчётов он пустой. Контрольный запуск проверяет ту же ссылку документа, исходную сумму и договор. После изменения объёма до 31 м³ сумма составляет 1 317,50 ₽. Помеченный на удаление расчёт исключается из обычной выборки.

## Воспроизведение на Windows

1. В отдельной папке скачайте исходники нужной версии. Для исходной схемы используйте `git worktree add --detach ../waterlab-v1 v1.0.0`.
2. В Конфигураторе новой файловой базы выполните «Конфигурация → Загрузить конфигурацию из файлов» из `app/models` версии 1.0.0 и обновите конфигурацию базы данных.
3. Запустите тонкий клиент с параметром `/C "waterlab-check|baseline|C:\Temp\waterlab-v1.txt"`. Папка для файла результата должна существовать. Выполните проверку один раз на пустой базе.
4. Загрузите `app/models` версии 1.1.0 в ту же базу и снова обновите конфигурацию базы данных.
5. Запустите тонкий клиент с `/C "waterlab-check|migration|C:\Temp\waterlab-v2.txt"`. Проверьте строки `PASS` и одинаковый идентификатор документа в обоих файлах.

Источники для учебной базы хранятся в `app/models`, а сгенерированную файловую базу и рабочие файлы Конфигуратора я исключил из Git.
